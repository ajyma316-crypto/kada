# QADA — قضاء الصلاة

Веб-приложение для расчёта, учёта и возмещения пропущенных обязательных намазов.

**Открыть приложение: https://kada-peach.vercel.app**

## Возможности

- **Калькулятор задолженности** — по дате/возрасту булюга (лунные или солнечные годы), дате начала регулярных намазов, доле совершённых намазов; для женщин — хайд и нифас; периоды без обязанности намаза; дополнительные перерывы; витр по мазхабу. Показывает разбивку, допущения, предупреждения и помечает приблизительные результаты знаком «≈».
- **Личный кабинет** — общая задолженность, восполнено, остаток, процент, прогресс за сегодня/месяц/всё время, серия дней, прогноз завершения.
- **Учёт** — +1 к каждому намазу, массовое добавление, отмена ошибочной отметки (мягкая — история сохраняется).
- **План** — по количеству в день, к целевой дате или по времени; сценарии «что если»; сравнение с фактическим темпом.
- **Статистика** — дни/недели/месяцы/годы, по видам намазов, календарь возмещения, график остатка, история отметок и изменений задолженности.
- **Правила и источники** — 4 мазхаба, сравнительная таблица, разногласия, классические источники, статус проверки.
- **Экспорт** — CSV, JSON (резервная копия и восстановление), печать/PDF-отчёт.
- **Офлайн (PWA)**, светлая/тёмная тема, русский, кыргызский и английский языки, синхронизация через Supabase.

## Запуск

```bash
npm install
npm run dev        # разработка
npm test           # тесты (логика расчётов, план, статистика, синхронизация, переводы)
npm run build      # сборка в dist/
```

Без настройки Supabase приложение полностью работает локально (данные в браузере).

## Публикация (Vercel)

Репозиторий подключается к Vercel как отдельный проект (Add New → Project). Настройки сборки берутся из `vercel.json`: перед публикацией запускаются тесты, затем сборка в `dist/`.
Переменные для облачной синхронизации задаются в Vercel → Project Settings → Environment Variables.

## Подключение Supabase (авторизация и синхронизация)

Опубликованное приложение подключено к проекту `kvpabwwwemolpsrruruc` — параметры в `.env.production` (только публичный ключ). Для своей копии:

1. Создайте проект на supabase.com.
2. Выполните `supabase/migrations/0001_init.sql` в SQL Editor (таблицы + Row Level Security).
3. Скопируйте `.env.example` в `.env` (локально) или задайте переменные в Vercel: `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
4. В Authentication → URL Configuration добавьте адрес, где размещено приложение.

## Архитектура

```
src/
  fiqh/rules.ts      — ВСЕ религиозные правила (данные, без UI): мазхабы, источники, статус проверки
  domain/            — чистая логика без React (можно перенести в мобильное приложение)
    calculator.ts    — расчёт задолженности
    ledger.ts        — задолженность / восполнено / остаток
    plan.ts          — сроки, нагрузка, сценарии
    stats.ts         — агрегации для аналитики
    merge.ts         — бесконфликтное слияние данных между устройствами
    dates.ts         — календарные дни и интервалы без ошибок часовых поясов
  data/
    store.ts         — состояние приложения в памяти + асинхронное сохранение (offline-first)
    persistence.ts   — хранение на устройстве: IndexedDB (отметки — отдельными записями),
                       перенос данных из старой версии (localStorage), запасной вариант
    sync.ts, cloud.tsx, supabase.ts — авторизация и синхронизация
  i18n/              — переводы (ru, ky, en)
  components/, pages/ — интерфейс
supabase/migrations/ — схема БД
```

**Модель данных.** Задолженность — сумма событий изменения (расчёт, ручная корректировка), восполненные намазы — журнал записей. Записи только добавляются, отмена — пометка `voidedAt`. Благодаря этому синхронизация между устройствами не теряет данные и не создаёт конфликтов; настройки/план — «последняя запись побеждает».

## Религиозная достоверность

Правила в `src/fiqh/rules.ts` собраны по общеизвестным положениям классических трудов мазхабов и **не проверены квалифицированным учёным** (`review.status: 'unverified'`), о чём приложение предупреждает. Для проверки специалисту достаточно отредактировать данные этого файла и выставить `review: { status: 'reviewed', reviewer, date }`.
